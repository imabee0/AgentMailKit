API-MISMATCH FINDINGS (assumed X -> actual Y)
================================================================
F1. axum ws: ASSUMED axum = "0.8" exposes axum::extract::ws::WebSocketUpgrade.
    ACTUAL: WebSocket support is behind the non-default "ws" feature.
    Fix: axum = { version = "0.8", features = ["ws"] }. Handler shape confirmed:
    async fn(State<Arc<S>>, ws: WebSocketUpgrade) -> impl IntoResponse { ws.on_upgrade(fn(WebSocket)) }.
    Note: axum 0.8 route params are "/messages/{id}" (":id" is a runtime panic, not a compile error).

F2. uuid in axum extractors: ASSUMED uuid features ["v4"] suffice.
    ACTUAL: Path<uuid::Uuid> needs the uuid "serde" feature; without it the whole
    handler fails an opaque `Handler<_, _> not implemented` E0277.
    Fix: uuid = { version = "1", features = ["v4", "serde"] }.

F3. mail-send 0.6: ASSUMED SmtpClientBuilder::new(host, port) is infallible.
    ACTUAL: new() -> Result<SmtpClientBuilder<T>, String> (builds the TLS connector).
    Chain: SmtpClientBuilder::new("host", 587)? .implicit_tls(false)
           .credentials(("user","pass")).connect().await? ; client.send(message).await?.
    connect()/credentials()/implicit_tls() names as assumed once past new().

F4. mail-auth 0.12 DKIM signing key: ASSUMED RsaKey::<Sha256>::from_pkcs1_pem.
    ACTUAL: canonical constructor is RsaKey::<Sha256>::from_key_der(rustls_pki_types::PrivateKeyDer).
    from_rsa_pem / from_pkcs8_pem / from_der still exist but are #[deprecated since 0.7.4].
    Signature::to_header() exists but requires importing trait mail_auth::common::headers::HeaderWriter.
    DkimSigner::from_key(key).domain(..).selector(..).headers([..]).sign(&raw) as assumed.
    Default features select the aws-lc-rs crypto backend + hickory DNS.

F5. mail-auth 0.12 verification: compiled EXACTLY as assumed — record of real names:
    MessageAuthenticator::new_cloudflare() (also new_system_conf etc.);
    AuthenticatedMessage::parse(&[u8]) -> Option<_>;
    .verify_dkim(&msg).await -> Vec<DkimOutput<'_>>, d.result() -> &DkimResult (Pass/Neutral/Fail/PermError/TempError/None);
    .verify_spf(mail_auth::spf::verify::SpfParameters::verify_mail_from(ip, ehlo_domain, host_domain, sender)).await -> SpfOutput, .result() -> SpfResult;
    .verify_dmarc(mail_auth::dmarc::verify::DmarcParameters::new(&msg, &dkim_outputs, "domain", &spf_output)).await -> DmarcOutput, .dkim_result()/.spf_result() -> &DmarcResult.

F6. smtp-proto 0.2: parser-only confirmed — request/response parsing + serialization,
    NO server/session engine (AgentMailKit must own the SMTP state machine).
    ASSUMED Request::parse yields Request<String>. ACTUAL:
    Request::<Cow<str>>::parse(&mut std::slice::Iter<'a, u8>) -> Result<Request<Cow<'a, str>>, Error>;
    variants Ehlo{host}, Helo, Lhlo, Mail{from: MailFrom<T> (.address: Cow<str>)}, Rcpt{to: RcptTo<T>},
    Bdat, Auth{mechanism: u64, initial_response}, Noop, ... Response<T: Display>::new(code, e1, e2, e3, msg)
    plus EhloResponse for the reply side.

F7. hickory-resolver 0.26 — three breaks vs the assumed (0.24/0.25-era) API:
    a) ASSUMED Resolver::builder_tokio()?.build() infallible. ACTUAL build() -> Result:
       let resolver: TokioResolver = Resolver::builder_tokio()?.build()?;
    b) ASSUMED typed MxLookup/TxtLookup iterables. ACTUAL mx_lookup/txt_lookup
       (macro-generated) return untyped Lookup; iterate lookup.answers() -> &[Record]
       and match hickory_resolver::proto::rr::RData::{MX, TXT}.
    c) ASSUMED accessor methods rec.data()/mx.preference()/mx.exchange(). ACTUAL these are
       now public FIELDS: rec.data, mx.preference (u16), mx.exchange (Name, .to_utf8()).
       TXT renders via Display (to_string()). No RData::as_mx()/as_txt() helpers.

F8. rmcp 3.1 (resolved 3.1.2) — pin "3.1" is real; macros work; two naming breaks:
    a) ASSUMED rmcp::handler::server::tool::Parameters. ACTUAL that path is private;
       public path is rmcp::handler::server::wrapper::Parameters.
    b) ASSUMED rmcp::model::Content. ACTUAL the content union is rmcp::model::ContentBlock
       (MCP 2025-11-25 spec); CallToolResult::success(Vec<ContentBlock>); ContentBlock::text(..).
    c) StreamableHttpService takes TWO generics <S, M: SessionManager>:
       StreamableHttpService::<MailTools, LocalSessionManager>::new(
           || Ok(MailTools::new()), LocalSessionManager::default().into(), Default::default())
       and mounts into axum via Router::nest_service("/mcp", service).
    Working tool shape (compiles):
       struct with field tool_router: ToolRouter<Self>; #[tool_router] impl block;
       #[tool(description = "...")] async fn f(&self, Parameters(req): Parameters<T>)
           -> Result<CallToolResult, rmcp::ErrorData>  where T: Deserialize + rmcp::schemars::JsonSchema;
       #[tool_handler] impl ServerHandler { fn get_info(&self) -> ServerInfo }.
    Transports exposed by this feature set: transport-io -> rmcp::transport::stdio()
    (serve via rmcp::ServiceExt::serve(stdio()).await, then .waiting().await);
    transport-streamable-http-server -> StreamableHttpService/StreamableHttpServerConfig
    (+ session managers via implied transport-streamable-http-server-session, e.g.
    streamable_http_server::session::local::LocalSessionManager). No SSE server and no
    websocket transport in this feature set (ws transport is commented out of rmcp 3.1.2 entirely).
